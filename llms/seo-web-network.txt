**Choosing between similar tools.** Several tools overlap deliberately.

- **Image Compressor vs Compress Image to Exact KB.** Both can target a size in KB. - **PDF Extract vs PDF Split.** Both produce pages from one PDF. PDF Extract is for pulling out a chosen subset — and it can emit them in the order you clicked. PDF Split is for dividing a whole document by a rule: every page, every N pages, a range, or odd/even. Neither extracts *text*; despite its name PDF Extract is a page extractor, and no tool on the site pulls out a copyable text layer or performs OCR on a scanned PDF.

- **PDF Compress vs Flatten PDF.** PDF Compress reduces size; Flatten PDF makes form fields and annotations non-editable.
- **JWT Debugger vs JWT Encoder.** Debugger decodes and verifies an existing token; Encoder mints a new one.
- **EMI Calculator vs Home/Car Loan Calculator.** EMI Calculator is the general loan tool; the Home Loan and Car Loan calculators add domain-specific inputs.

The sitemaps.org protocol caps a single sitemap at 50,000 URLs and 50MB uncompressed. This tool enforces that limit and tells you to split into multiple files under a sitemap index if you exceed it.

Split your URLs into multiple sitemap files, each under the limit, then create a sitemap index file listing all of them and submit only the index URL to search engines.

It still helps - a sitemap gives search engines a direct, authoritative list of canonical URLs and lastmod hints, speeding up discovery beyond what crawling links alone would achieve.

No - it aids discovery, but indexing still depends on content quality, crawl budget, and technical accessibility. It's a discovery aid, not an indexing guarantee.

Whenever you add, remove, or significantly update pages - for actively changing sites, monthly or as part of your deploy process keeps search engines working from current data.

#### Frequently asked questions (25)

**What is DNS lookup?**
DNS lookup is the process of querying the Domain Name System to retrieve the records associated with a domain — such as its IP address (A/AAAA), mail servers (MX), or text records (TXT) — translating human-readable names into the machine-readable data that powers the internet.

**How does DNS work?**
When you look up a domain, a recursive resolver asks a root name server which server handles the domain's TLD, then asks that TLD server which name server is authoritative for the exact domain, and finally asks that authoritative server for the actual record — a process called recursive resolution.

**What is an A record?**
An A record maps a domain name to an IPv4 address, such as example.com pointing to 93.184.216.34. It's the most fundamental DNS record type, used by browsers to know where to connect.

**What is an AAAA record?**
An AAAA record maps a domain name to an IPv6 address, the 128-bit successor to IPv4 designed to accommodate the internet's growth beyond IPv4's address space.

**What is an MX record?**
An MX (Mail Exchange) record specifies which mail servers accept email for a domain, along with a priority number — lower numbers are tried first — so a domain can list backup mail servers.

**What is a TXT record?**
A TXT record stores arbitrary text data attached to a domain, commonly used for SPF, DKIM, DMARC, domain ownership verification, and other machine-readable metadata.

**What is an SPF record?**
SPF (Sender Policy Framework) is a TXT record listing which mail servers are authorized to send email on behalf of a domain, helping receiving servers reject forged 'from' addresses.

**What is a DMARC record?**
DMARC (Domain-based Message Authentication, Reporting & Conformance) is a TXT record at _dmarc.yourdomain.com that tells receiving mail servers what to do with messages that fail SPF or DKIM checks, and where to send reports.

**What is a DKIM record?**
DKIM (DomainKeys Identified Mail) publishes a public key at a selector subdomain (like selector._domainkey.yourdomain.com) so receiving servers can verify a cryptographic signature added to outgoing mail, proving it wasn't altered in transit.

**How do I check DNS records for a domain?**
Enter the domain into this tool, choose a record type or 'All Records', and click Lookup — results come back in seconds directly from public DNS-over-HTTPS resolvers.

**How often do DNS records update?**
Updates depend on the record's TTL (time to live). A record with a 3600-second TTL can take up to an hour to be reflected everywhere, since resolvers cache the old value until it expires.

**Why are my DNS changes not visible yet?**
DNS propagation isn't instant — different resolvers around the world cache records for different durations based on TTL, so changes can take anywhere from minutes to 48 hours to be visible everywhere.

**What is TTL in DNS?**
TTL (Time To Live) is the number of seconds a resolver is allowed to cache a DNS record before re-querying the authoritative server, balancing update speed against query load.

**What is DNSSEC?**
DNSSEC (Domain Name System Security Extensions) cryptographically signs DNS records so resolvers can verify they weren't tampered with in transit, protecting against cache poisoning and spoofing attacks.

**Can I look up subdomains?**
Yes — enter any subdomain or hostname, such as api.example.com or mail.example.com, exactly as you would a root domain.

**Can I check email authentication records?**
Yes — this tool automatically checks SPF and DMARC, and includes a one-click check against common DKIM selectors to find published DKIM keys.

**Can I export the results?**
Yes — export any lookup as JSON, CSV, or plain TXT, copy a formatted summary to your clipboard, print the page, or copy a shareable link that reruns the same lookup.

**Is this DNS lookup tool free?**
Yes — completely free, with no signup, no rate limits, and no watermarked results.

**Does it work on mobile?**

**Is DNS lookup secure and private?**
Lookups are sent directly from your browser to public DNS-over-HTTPS resolvers (Google and Cloudflare) over encrypted HTTPS — ToolAdda's own servers never see or log the domains you search.

**What is a CNAME record?**
A CNAME (Canonical Name) record aliases one domain name to another, so all DNS queries for the alias are redirected to the target domain's records instead.

**What is an NS record?**
An NS (Name Server) record identifies which servers are authoritative for a domain, i.e., which servers hold the master copy of its DNS records.

**What is a SOA record?**
An SOA (Start of Authority) record holds administrative information about a DNS zone: the primary name server, admin contact, serial number, and timing values like refresh, retry, and expire.

**What is a PTR record?**
A PTR (Pointer) record maps an IP address back to a domain name — the reverse of an A record — used for reverse DNS lookups, mail server verification, and network diagnostics.

**What is a CAA record?**
A CAA (Certification Authority Authorization) record specifies which certificate authorities are permitted to issue TLS/SSL certificates for a domain, reducing the risk of mis-issued certificates.

#### Frequently asked questions (25)

**What is DNS propagation?**
The process by which a DNS change becomes visible across resolvers worldwide, governed by TTL and each resolver's independent cache.

**How long does DNS propagation take?**
It depends on the record's TTL — a record with a 300-second TTL can be fully visible within 5 minutes of expiry, while one left at a default 86400-second (24-hour) TTL can take up to a full day on any given resolver.

**Why are my DNS changes not visible yet?**
Resolvers that already cached the old record won't re-check the authoritative server until that cached entry's TTL expires — so it isn't broken, it's just waiting out the cache window.

**What is TTL?**
TTL (Time To Live) is the number of seconds a resolver is allowed to cache a DNS answer before it must re-query the authoritative server for a fresh value.

**Why do different resolvers show different results?**
Each resolver caches independently based on when it first saw the record and that record's TTL, so during the propagation window it's normal and expected for some resolvers to still return the old value while others already show the new one.

**What is DNS cache?**
A DNS cache is a temporary local store of previously resolved DNS answers, kept by resolvers (and browsers and operating systems) to avoid repeating the same lookup, discarded automatically once the record's TTL expires.

**Can I force DNS propagation?**
Not directly — you can't force other resolvers to drop their cache, but lowering the record's TTL well before a planned change shortens the natural propagation window for the next update.

**Does Cloudflare speed up propagation?**
Cloudflare's own authoritative DNS is very fast to publish changes, but it can't force third-party resolvers elsewhere to expire their cache early — propagation to the wider internet still follows each resolver's cached TTL.

**How often should I refresh a propagation check?**
Every few minutes is reasonable for a short-TTL record; this tool's auto-refresh option can re-check every 30 seconds automatically while you wait.

**Can I check MX propagation?**
Yes - select MX to see mail server and priority changes across resolvers.

**Can I verify TXT record propagation?**
Yes — TXT is fully supported, useful for confirming SPF, DKIM, DMARC, or domain-verification TXT records have gone live.

**Does this tool check DNS propagation worldwide?**
It queries four independently operated public DNS resolver networks (Google, Cloudflare, DNS.SB, and RethinkDNS) that are used by a large share of internet traffic globally — a strong practical signal, though it is not a literal probe from every country, since this tool runs entirely in your browser with no backend server network.

**Is my lookup secure and private?**
Yes — every query is sent directly from your browser to each resolver over encrypted HTTPS; ToolAdda's own servers never see or log the domains you check.

**What happens if propagation shows as failed?**
A 'failed' resolver means that specific resolver didn't respond to the query (often a transient network issue) — the tool lets you retry just the failed resolvers without re-running the whole check.

**How accurate are the results?**
Results are the real, live answers returned by each resolver at the moment you run the check — nothing is cached, simulated, or estimated by this tool itself.

**Can I monitor propagation continuously?**
Yes — enable auto-refresh to automatically re-check every 30 seconds while you keep the page open, useful while waiting out a TTL window.

**Why do different ISPs update at different times?**
Each ISP typically runs (or contracts) its own resolver infrastructure with its own cache state, so the exact moment an ISP's users see a DNS change depends on when that ISP's resolver last cached the old value.

**Why isn't there a literal world map with country markers?**
A real per-country map requires probe servers physically deployed in each location. This tool runs entirely in your browser with no backend, so every query genuinely originates from wherever you are — labeling that as 'Germany' or 'Japan' would be fabricated. Instead, it shows real, honestly-labeled results from four independent resolver operators.

**What is a DNS resolver?**
A DNS resolver is a server that looks up DNS records on behalf of a client, following the chain from root servers to TLD servers to the authoritative server, then caching the answer for future requests.

**What does 'consensus' mean in this tool?**
Consensus is the answer returned by the largest group of checked resolvers; a resolver 'matches consensus' when its returned value agrees with that majority answer.

**Can I check an expected value specifically?**
Yes — enter the exact value you expect (like a new server IP) in the optional 'expected value' field, and each resolver row will show whether it matches that specific value rather than just general consensus.

**Does DNSSEC affect propagation?**
DNSSEC doesn't change propagation timing, but a broken DNSSEC signature chain after a change can cause validating resolvers to reject the new record entirely (SERVFAIL) rather than simply serving a cached old value — this tool surfaces that distinction.

#### Frequently asked questions (18)

**How accurate is this internet speed test?**
It measures real transfers over your actual connection using eight parallel streams to a Cloudflare endpoint, discards the first second while TCP ramps up, and falls back to other providers if Cloudflare is blocked. That makes it comparable to any other browser-based test. What no browser test can do is bypass your Wi-Fi, your device or the browser itself, so treat the number as the speed available to this device right now rather than the speed on your line.

**Why is my speed lower than the plan I pay for?**
Almost always Wi-Fi rather than the line. A plan is sold as the speed to your router; what a laptop in another room sees after walls, interference and an older Wi-Fi standard can be a fraction of it. Test again with an Ethernet cable, or standing next to the router, and compare the two numbers before contacting your provider.

**What is a good internet speed?**
For one person browsing and streaming HD, 25 Mbps is comfortable. A household with 4K televisions and several people working wants 100 Mbps or more. Beyond about 200 Mbps most people stop noticing improvements, because the bottleneck moves to the servers you are talking to rather than your connection.

**What do download and upload speed actually mean?**
Download is how fast data reaches you, which decides streaming, browsing and downloads. Upload is how fast data leaves you, which decides video calls, cloud backups and sending large files. Most home connections are deliberately asymmetric, with upload a small fraction of download.

**What is ping and why does it matter?**
Ping is the round trip time for a small packet, in milliseconds. It has nothing to do with bandwidth: a very fast connection can still have terrible ping. It is what decides whether a video call feels natural and whether an online game is playable, so it matters more than raw speed for anything interactive.

**What is jitter?**
Jitter is how much the ping varies from one packet to the next. Steady 60 ms is fine; a ping that swings between 20 ms and 200 ms has high jitter and will break up calls and live video even though the average looks acceptable. Under 20 ms is comfortable for calls.

**Why is my upload speed so much lower than download?**
Because that is how most home broadband is designed. Cable and DSL reserve far more capacity for download because that is what households mostly do. Fibre connections are often symmetric, with upload matching download. A very low upload only becomes a problem when you make video calls or back up large files.

**Does Wi-Fi slow down my internet speed?**
Yes, often substantially. Distance, walls, interference from neighbouring networks and older hardware all reduce what reaches your device. The most useful diagnostic is to run this test once over Wi-Fi and once over Ethernet: if the wired result matches your plan, the problem is your Wi-Fi rather than your provider.

**How can I make my internet faster?**
Move closer to the router or use Ethernet, switch to the 5 GHz band if your router offers one, restart the router, and check nothing else on the network is downloading in the background. If the wired speed is still well below your plan, the issue is with the line or the provider and is worth reporting.

**Why does my speed change every time I test?**
Real connections vary with network congestion, what else is using your connection, and which server you reach. Run the test a few times at different moments and use the pattern rather than any single number. The tool keeps your recent results so you can see that pattern.

**Does this speed test use my data allowance?**
Yes. A full test transfers real data — typically tens to a few hundred megabytes depending on how fast your connection is, because a faster line moves more data in the same fixed time. On a metered or mobile connection, run it sparingly.

**Is my speed test result sent anywhere?**
No. The test runs in your browser and the results are stored only in your own browser's local storage so you can compare runs. Nothing is uploaded to ToolAdda and there is no account. The measurement traffic itself necessarily goes to a public test endpoint, which is how any speed test works.

**Which servers does the test use?**
It measures against Cloudflare's public speed endpoint by default. If that is unreachable — some corporate and school networks block it — it automatically falls back to large incompressible files on a public CDN, and then to other public endpoints. The result panel names the provider that was actually used.

**Why does the test need incompressible files?**
Because a compressed text file would be sent over the network in a small compressed form and then expanded by the browser. Counting the expanded bytes would report a speed several times higher than the real transfer. This test deliberately uses already-compressed data, such as JPEG images, so the bytes counted are the bytes that actually crossed the network.

**Do I need to close other apps before testing?**
It helps. Anything else downloading, syncing or streaming is competing for the same connection and will lower your result. For a clean measurement, pause large downloads and cloud backups first.

**Can I test the speed on my phone?**
Yes, the test works the same on a phone or tablet. Bear in mind it will measure your Wi-Fi or mobile connection as your phone sees it, and that a mobile test consumes data from your plan.

**What is Mbps, and how is it different from MB/s?**
Mbps is megabits per second and is how internet plans are sold. MB/s is megabytes per second and is what a download manager shows. There are eight bits in a byte, so a 100 Mbps connection downloads at about 12.5 MB/s at best — which is why a fast plan can look slow in a download window.

No. It runs entirely in your browser with no app, plugin, sign-up or Flash. Open the page and press start.
