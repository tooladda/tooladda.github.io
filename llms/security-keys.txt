#### Frequently asked questions (31)

**Is this password generator actually cryptographically secure?**
Yes. Every character is chosen using the browser's Web Crypto API (crypto.getRandomValues), the same cryptographically secure source used by TLS and password managers — not Math.random(), which is not designed for security. This tool also uses rejection sampling to eliminate modulo bias, a subtle flaw where naive implementations slightly favor certain characters.

**What is modulo bias and why does it matter?**
Mapping a random number to a smaller range with % can slightly favor certain values unless handled carefully. This tool rejects and re-draws any value that would introduce bias, so every character has a truly equal chance.

**Are my generated passwords stored anywhere?**
No, and this is deliberate: the on-page history is kept only in memory for your current session and is wiped the moment you reload or close the tab — it is never written to localStorage, a cookie, or any server. Only non-sensitive settings like your preferred length and character toggles are optionally remembered.

**What password length should I use?**
Use at least 16 characters for important accounts, and 20+ for anything protecting significant value (email, banking, password manager master password). Length increases security exponentially — each additional character multiplies the number of possible combinations, making length the single most impactful setting you control.

**What is password entropy?**
Entropy, measured in bits, quantifies how unpredictable a password is. Each additional bit doubles the number of guesses an attacker needs. A random 16-character password using upper, lower, numbers, and symbols has roughly 105 bits of entropy — effectively unguessable with current technology — while a dictionary word has only a handful of bits no matter how long it looks.

**Is a longer password always better than a complex one?**
Generally yes. A 20-character password using only lowercase letters (95 bits of entropy) is harder to brute-force than an 8-character password using every character type (about 52 bits). Complexity matters, but length matters more — this is why modern guidance (like NIST SP 800-63B) emphasizes length over forced complexity rules.

**Are passphrases as secure as random passwords?**
A passphrase of enough random, independently-chosen words can match or exceed a random password's entropy while being far easier to remember and type — six words from this tool's 300+ word list give roughly 50 bits, and eight words give about 67 bits. The key is that the words must be chosen randomly (as this tool does), not picked by you, since human-chosen phrases are far more predictable.

**What is a brute-force attack?**
A brute-force attack systematically tries every possible character combination until it finds the correct password. Its feasibility depends entirely on password length and character variety — this tool's crack-time table shows how long a brute-force attempt would realistically take against your generated password under several real-world attacker scenarios.

**What is a dictionary attack?**
A dictionary attack tries real words, common passwords, and known-leaked passwords (often with predictable tweaks like adding '123' or a capital letter) instead of every possible combination — which is why 'Password123!' is weak despite looking complex, while a truly random string of the same length is not, since it isn't found in any dictionary.

**What is credential stuffing and how do unique passwords stop it?**
Credential stuffing takes username/password pairs leaked from one breached site and automatically tries them on many other sites, exploiting the fact that people reuse passwords. Generating a unique password for every account — exactly what this tool is for — means a breach on one site can never unlock your accounts elsewhere.

**Should I use a password manager with this generator?**
Yes, strongly recommended. Generate a unique password here for each account, then save it in a reputable password manager rather than a note, spreadsheet, or your memory — that combination gives you both strong, unique passwords and a practical way to actually use them across dozens of accounts.

**Does a strong password mean I don't need two-factor authentication (MFA)?**
No — a strong password and MFA solve different problems and should be used together. A strong, unique password prevents guessing and reuse-based attacks; MFA protects you even if your password is somehow phished or leaked, since the attacker would still need your second factor (an authenticator app, security key, or similar) to get in.

**How does this tool estimate crack time?**
It uses zxcvbn, the realistic password-strength library originally built by Dropbox, which models real attacker knowledge (dictionaries, common patterns, keyboard walks, leetspeak substitutions) rather than naive character-count math. Crack time is then shown across five scenarios, from a rate-limited login form to a large-scale GPU cracking cluster, since the 'right' answer depends entirely on what an attacker can actually do.

**Why do the same password's crack times vary so much between scenarios?**
Guess rate varies by many orders of magnitude depending on the attack: a login form with rate-limiting might allow only 100 guesses per hour, while an attacker who has stolen a poorly-hashed database and runs it offline on GPUs can try tens of billions of guesses per second. The same password can be 'centuries' safe in one scenario and 'instant' in another.

**What does 'exclude similar characters' do?**
It removes characters that are easy to confuse when read or typed, like lowercase l, uppercase I, the digit 1, uppercase O, and the digit 0 — useful when you'll be reading a password aloud, typing it on a device without autofill, or writing it down temporarily.

**What does 'exclude ambiguous characters' do?**
It removes symbols that can behave unpredictably in some software or are awkward to type, such as brackets, quotes, backslashes, and punctuation like commas and semicolons — handy when a specific website's password field has undocumented character restrictions.

**What does "avoid sequential characters" prevent?**
Rejects results containing a 3-character ascending or descending run like "abc" or "789" - exactly what pattern-matching attacks check for.

**What does 'no repeating characters' mean here?**
It prevents the same character from appearing twice in a row (like 'aa' or '77'), which slightly increases unpredictability and avoids passwords that look obviously patterned, without the impossible constraint of banning every character from repeating anywhere in a long password.

**Can I set a custom character set?**
Yes. Any characters you type into the Custom Character Set field are added to the pool alongside whichever standard character types you've enabled — useful for sites that require a specific special character, or non-English character requirements.

**Can I make a password start or end with specific text?**
Yes, using the Start With and End With fields. The rest of the password is still filled with cryptographically random characters up to your chosen total length — useful for meeting a site's specific format rule or for building a recognizable-but-still-random API key prefix.

**What's the difference between a strong password and a passphrase?**
A password mixes random individual characters for maximum entropy per character typed; a passphrase strings together multiple random dictionary words, trading a bit of entropy-per-character for something dramatically easier for a human to remember and type accurately. Both are cryptographically random here — the choice is about your own memorability needs.

**What is a pronounceable (memorable) password?**
It's a randomly generated string built from alternating consonant-vowel syllables (like 'fenoraku'), which reads more like a real word and is easier to type accurately from memory than fully random characters, while still being generated with the same cryptographically secure randomness.

**How long should a PIN be, and does length matter as much as for passwords?**
A 4-digit PIN has only 10,000 possible combinations — trivial to brute-force without a lockout mechanism — so use the longest PIN your device or service allows (6+ digits where possible), and enable this tool's common-PIN and sequential-digit avoidance to skip the values attackers try first.

**What format should I use for an API key?**
Hex is the most universally compatible and human-readable in logs; Base64URL packs more entropy per character and is safe to use directly in URLs; UUID v4 is useful when a system specifically expects that format. All three, generated here, use the same cryptographically secure random bytes underneath.

**Is it safe to generate a Wi-Fi password with this tool?**
Yes. WPA2/WPA3 accept 8 to 63 printable ASCII characters, and this tool's Wi-Fi tab defaults to a strong length within that range, with an 'easy to type' option that avoids similar and ambiguous characters — helpful since Wi-Fi passwords are often typed on TVs, consoles, or other devices with awkward on-screen keyboards.

**What's the risk of scanning a QR code of my password?**
A QR code just encodes your exact password as a scannable image — anyone who can see or photograph that image can read the password, so treat it exactly as sensitively as the password itself. It's a convenient way to transfer a password to a phone or another device you control, not something to post, screen-share, or store loosely.

**How many passwords can I generate at once?**
Up to 200 in a single batch using the bulk generator, which you can then download as a TXT or CSV file — useful for provisioning many accounts, test users, or temporary credentials at once.

**Does this password generator work offline?**
Yes - once loaded, generation, strength scoring, and QR export all run locally with no network requests.

**What are common password mistakes to avoid?**
Reusing the same password across sites, using personal information (names, birthdays, pet names), predictable substitutions like '@' for 'a', keyboard walks like 'qwerty', and passwords under 12 characters are the most common mistakes — all of which are exactly what dictionary and pattern-matching attacks check first.

**What should a business password policy require?**
Modern guidance (e.g. NIST SP 800-63B) recommends a generous minimum length (12-16+ characters) over forced complexity rules or frequent mandatory rotation, screening new passwords against known-breached password lists, enforcing MFA everywhere feasible, and using a company-approved password manager rather than relying on employees to remember unique passwords unaided.

Yes — completely free, no account, no features locked behind an account, and no cap on how many passwords, passphrases, PINs, or keys you generate.

#### Frequently asked questions (31)

**Is my password sent anywhere when I use this checker?**
No. Every calculation happens in your browser using JavaScript that runs locally. Your password is never transmitted, and it is never written to localStorage or cookies. You do not have to take our word for it: disconnect from the internet and the checker keeps working exactly as before, because there is nothing for it to call.

**What is zxcvbn and why does it matter?**
zxcvbn is a realistic password strength estimator originally built by Dropbox. Instead of just counting uppercase letters, digits, and symbols, it models how real attackers actually guess — dictionary words, names, keyboard walks like 'qwerty', dates, repeats, sequences, and common leetspeak substitutions like '@' for 'a' — giving a far more honest strength estimate than character-counting checkers.

**How does password strength actually work?**
It's about how many guesses an attacker realistically needs, not how complex a password looks. A dictionary word plus substitutions can crack instantly despite looking complex; random unrelated words can take centuries despite looking simple.

**What is password entropy, exactly?**
Entropy measures unpredictability in bits; each extra bit doubles the guesses needed. This tool shows two entropy numbers: 'real entropy' derived from zxcvbn's pattern-aware guess count (what actually matters), and 'naive pool-based entropy' — what a simplistic character-counting checker would report, which is usually a big overestimate since it assumes every character is equally random.

**How is crack time actually estimated?**
Crack time = estimated guesses required ÷ guesses per second an attacker can make. Guesses per second varies enormously by scenario — a rate-limited login form might allow under 100 guesses per hour, while an attacker running stolen, poorly-hashed data on GPUs can try tens of billions of guesses per second — so this tool shows crack time across 5 realistic scenarios rather than one misleading number.

**What is a brute-force attack?**
A brute-force attack tries every possible character combination systematically until one works. It's the slowest, most exhaustive method and is why length matters so much — every additional character multiplies the total combinations an attacker must exhaust.

**What is a dictionary attack?**
A dictionary attack tries real words, names, and known-leaked passwords first — including predictable tweaks like a capital first letter or '123' appended — before resorting to brute force. This is why 'Password123!' is weak despite mixing character types: it's a dictionary word plus tweaks the attacker's wordlist already anticipates.

**What are rainbow tables, and does a strong password protect against them?**
A rainbow table is a precomputed lookup of hash values mapped back to the plaintext that produced them, letting an attacker reverse a stolen hash instantly instead of computing it fresh. Properly implemented sites defeat rainbow tables with 'salting' (adding a unique random value to each password before hashing), which is a server-side defense — but a longer, more random password still helps, since it wouldn't appear in a precomputed table even without salting.

**What is credential stuffing?**
Credential stuffing takes username/password pairs leaked from one breached site and automatically tries them on many other sites, exploiting password reuse. A strong, unique password per account fully defeats it, since a breach elsewhere becomes irrelevant to accounts using a different password.

**Does this tool check my password against real data breaches like Have I Been Pwned?**
Not via a live query — this tool checks your password against a curated local list of the most common passwords found in public breach research (like NordPass's and SplashData's annual "worst passwords" reports), entirely offline. It intentionally does not call any external API like Have I Been Pwned, because doing so would require sending at least part of your password's hash over the network, which this page deliberately never does. For a live breach check, use a dedicated service directly.

**How long should a password be?**
Length matters more than complexity. A random 16+ character password, or a 6-word random passphrase, is far stronger than an 8-character password stuffed with symbols, because every extra character multiplies the number of guesses an attacker needs — this is also the core recommendation in NIST's current digital identity guidelines (SP 800-63B).

**Are symbols necessary for a strong password?**
Not as much as people think. Adding one symbol to a short, dictionary-based password barely slows an attacker who already tries common substitutions like '@' for 'a' or '0' for 'o'. A longer password or passphrase without any symbols is usually stronger than a short one with symbols crammed in.

**Is a passphrase better than a traditional password?**
Often yes, and it's easier to remember and type correctly. Several random, unrelated words strung together create a long password with strong guess-resistance, without needing to memorize symbol substitutions — the words just need to be chosen by a random process, not by you.

**What is multi-factor authentication (MFA) and do I still need it with a strong password?**
MFA (or 2FA) requires a second proof of identity beyond your password — a code from an authenticator app, a hardware key, or a biometric check. Yes, you still need it: MFA protects you even if a strong password is somehow phished or leaked from a breach, since a password alone stops being enough to log in.

**Should I use a password manager?**
Yes. A password manager generates and remembers a unique, random password for every account, so you only need to remember one strong master password or passphrase — it's the practical way to actually use unique, high-entropy passwords across dozens of accounts without writing them down insecurely.

**What should a business password policy look like?**
Modern guidance favors a generous minimum length over forced complexity rules, screening new passwords against known-breached lists, dropping mandatory periodic rotation for passwords that haven't been compromised (which tends to produce weaker, more predictable passwords over time), and mandating MFA plus a company-approved password manager wherever feasible.

**What's the difference between 'real entropy' and 'naive entropy' shown on this page?**
Naive entropy assumes every character in your password is equally random given the character types present — length × log2(pool size) — which overestimates strength for anything containing patterns. Real entropy is derived from zxcvbn's actual guess-count estimate, which accounts for dictionary words, patterns, and known substitutions, and is the number that reflects real-world crack resistance.

**Why do the same password's crack times vary so much between scenarios?**
Guess rate varies by many orders of magnitude depending on the attack: a throttled login form might allow only ~100 guesses per hour, while an attacker who has stolen a poorly-hashed database and runs it offline on GPUs can try tens of billions of guesses per second — the same password can be effectively uncrackable in one scenario and instant in another.

**What are keyboard patterns, and why are they weak?**
Keyboard patterns are sequences typed by moving along the keyboard layout rather than choosing random characters — like 'qwerty', '1qaz2wsx', or 'asdfgh'. They look random at a glance but are among the very first patterns any real password-cracking tool checks, since they're extremely common.

Common causes include an expired certificate, a hostname mismatch, an incomplete certificate chain, or a self-signed certificate that browsers don't trust. The checker highlights these issues so you can fix them.

**What is the difference between SSL and TLS?**
TLS (Transport Layer Security) is the modern successor to SSL (Secure Sockets Layer). SSL is deprecated, but the name stuck - today an "SSL certificate" actually secures connections using TLS 1.2 or TLS 1.3.
